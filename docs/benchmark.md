# Benchmark protocol

The executable research benchmark lives in `benchmark/manifest.json` and is currently explicitly pending. This is the historical formal publication manifest. The current workbook/reference and pinned captures are available in the private result package, with an observed comparison route described in the V3 report; independently approved codebook and original sampling provenance remain absent. Synthetic data is located under `benchmark/synthetic/` and its outputs under `benchmark/results/synthetic-v1/`.

Required research manifest fields are described in `benchmark/provenance/import_specification.md`. Config paths are relative to the project root; configs must live directly in `<project>/configs/`. Snapshot/provenance paths are relative to the manifest directory. Traversal outside these roots is rejected; place input files under the benchmark directory instead of using `..` paths. Outputs are new directories and never overwrite existing runs.

Research runs require a clean committed checkout and a lockfile. Put local acquired/imported private material and runs under ignored directories while preparing the release, then review approved input manifests/snapshots before committing them. A separately prepared complete research benchmark directory can be supplied via a new config in the project's configs directory. Do not publish annotation notes or private workbook copies automatically.

All 100 research repositories need explicit immutable commits and six literal binary approved labels. The label table checksum must match the annotation provenance, the provenance hash must match the benchmark manifest, and manifest labels must match approval-referenced table rows. Independent labels and missing cells must remain separate from gold. The older formal validator assumes complete binary annotations and 247 disagreements; the audited source instead has 246 valid disagreements and one missing pair. Do not force the missing value into that legacy schema; use the observed comparison route until the formal protocol is adjudicated. The human codebook and sampling documentation each require content checksums, and the codebook requires an approval reference.

Exploratory evaluation is the default research config role. A held-out role is only allowed with a documented split approval and no declared development overlap. A held-out declaration cannot erase prior use of the benchmark to tune rules. Final paper results require an approved protocol and the implemented split/freeze/evaluation-ledger guards; software validation alone is not scientific approval.

## v0.2.0 protocol update

Documentation-only is primary, with development macro-F1 for model selection. Documentation uses explicit, contextual and demonstrated-workflow families with activity/object/scope/polarity records; wrapped prose and inherited Markdown/AsciiDoc/reStructuredText headings are supported. Production matching is deterministic and uses no gold labels or external models. Both the verified `final_agreement` mapping and legacy `Agreement Final` mapping are supported; independent labels remain separate provenance. See `agreement_final.md`, `evaluation_protocol.md` and `rule_change_protocol.md` for the current importer, split, freeze, mismatch and final-run procedures. Historical one-line rules and unsplit held-out declarations are superseded. This describes the historical V2 protocol. The original workbook has now been audited and observed reference comparisons have been run; see [the V3 implementation report](implementation_report_20261015.md) for actual measurements and their limits.
