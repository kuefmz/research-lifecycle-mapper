# Reproducing predictions and reports

Python is pinned to 3.12.14 in `.python-version`, CI and the convenience Dockerfile. `uv.lock` resolves exact versions, distribution URLs and hashes for the build/development environment. Runtime dependencies are standard-library only. Use uv 0.12.23 and `uv sync --frozen`. Runtime microversion is included in each execution manifest. Package installation must be prepared/cached before a completely network-free fresh-machine run.

Input identity consists of canonical repository ID, immutable commit, policy version, inventory statuses, eligible raw-content hashes and canonical snapshot-manifest hash. Live acquisition uses immutable blobs after resolving the commit; it does not follow mutable default branches during downloads. A recursive GitHub tree truncation aborts rather than silently yielding a partial inventory. Unavailable eligible files and Python parse errors mark affected mode scans incomplete. Size exclusions are recorded as unavailable rather than silently ignored.

Replay validates manifest serialization, policy, repository/commit identity, sorted unique inventory, source eligibility and every captured byte hash/size. Stored original line endings are preserved for hashing and evidence extraction. Symlink/path traversal is rejected. Supplied benchmark manifests pin each snapshot manifest checksum. SHA-256 integrity protects supplied artifacts against accidental alteration; a trusted curator must approve the root manifest. It is not a digital signature system.

Canonical outputs are `manifest.json`, `predictions.csv`, `evidence.jsonl`, `excluded_evidence.jsonl`, `metrics.json`, `metrics.csv`, `confusion_matrices.csv`, `confusion_matrices.svg`, `errors.csv`, `coverage.csv`, and `report.md`. `environment.json` records platform/machine details and is intentionally outside the canonical comparison set. There are no wall-clock timestamps. Git commit, source dirty state and a deterministic implementation-content hash distinguish committed and experimental checkouts; research runs require a clean commit. JSON is UTF-8, sorted keys, no non-finite numbers; CSV uses fixed column/row order and LF terminators; metrics are rounded to eight decimals.

`benchmark verify` reruns the same config twice and compares SHA-256/bytes for **every canonical output**, including the current manifests. `--reference` additionally compares semantic output artifacts against a previous reference, excluding only that reference's producing manifest because a later commit naturally has different provenance. This is a separate comparison from same-input/current-version exact reproducibility. The original reference manifest is retained and never rewritten. It is not claimed to be an identical full run across different classifier commits/environments.

Snapshot bundles are uncompressed tar archives with deterministic member ordering, zero timestamps/owners and fixed permissions. Only captured content and its manifest are included. Distribution requires explicit license/policy review. Synthetic snapshot bundles are allowed. For unredistributable inputs, share allowed manifests, revisions, hashes and the acquire command, clearly recording unavailable content. Re-fetching from GitHub is not guaranteed to be identical or available; reproducibility of published canonical results requires the originally captured snapshots or an explicitly documented limitation.

The Dockerfile pins a Python version tag, not a verified image digest, and CI action major tags are mutable. No container build was executed in this workspace. Before freezing, resolve/record verified OCI and action digests, archive wheels and inputs where licensed, freeze the clean classifier commit and run the release reproduction check in that environment. The current lockfile/explicit runtime is a reproducible dependency definition, not a claim of fully bit-identical OS images.

## v0.2.0 protocol update

Documentation-only is primary, with development macro-F1 for model selection. Documentation uses explicit, contextual and demonstrated-workflow families with activity/object/scope/polarity records; wrapped prose and inherited Markdown/AsciiDoc/reStructuredText headings are supported. Production matching is deterministic and uses no gold labels or external models. Agreement Final is the required candidate consensus worksheet; independent labels remain separate provenance. See `agreement_final.md`, `evaluation_protocol.md` and `rule_change_protocol.md` for the current importer, split, freeze, mismatch and final-run procedures. Historical one-line rules and unsplit held-out declarations are superseded. Human inputs are still missing; no human tuning or held-out run was performed.
